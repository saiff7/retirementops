# ADR-008: Mock JWT identity locally; OAuth 2.1 at the Cloudflare edge

**Status:** Accepted (2026-11-26)

## Context
Authorization must be enforced by servers. A real SSO integration is out of scope.

## Decision
- **M1 to M5 (local):** the API issues and verifies short-lived JWTs (RS256, dev keypair generated by a
  script into a git-ignored path). A dev login page in the UI lets you pick a seeded fictional user:
  `op.alex`, `rev.sam`, `rev.lee` (second reviewer for four-eyes), `comp.jo`, `comp.ria`, `admin.kim`. Each has roles, scopes and assigned tenants. The UI
  labels this "**Mock identity — not production SSO**".
- **Assignments are re-checked on every request.** The token proves identity (`sub`) and carries the
  requested scopes. On each request the API loads the user's current roles and tenant assignments from
  `app.users`. Effective scopes are the token's scopes **intersected** with the scopes of the roles held
  now, and the tenant set always comes from the DB, never from the token. A revoked role or a removed
  tenant therefore takes effect immediately.
- **Agent run tokens** are minted by the orchestrator through an internal API call that requires the
  starting human operator's session. They are bound to `run_id` and `tenant_id`, carry only the agent
  scopes and expire after 10 minutes.
- **M6 (edge):** the Workers OAuth Provider issues OAuth 2.1 tokens (authorization code with PKCE) to
  MCP clients with scopes from the architecture.md matrix. The Worker checks the scope per tool and then
  calls the Python API with (a) its gateway service credential (a Wrangler secret) and (b) the verified
  principal and scopes in a signed header. The API checks both.
- Secrets live in `.env` (local, git-ignored, with `.env.example` containing placeholders) and in
  Wrangler secrets (deployed). Logging redacts `Authorization` headers and any `token` key.

## Consequences
- Role separation and scope tests can run offline.
- Not production identity. The docs and UI say so.
